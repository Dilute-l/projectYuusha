> 依据 `docs/candidates_index.md` 里的 42 位候选人排的。**60 个位置，42 张卡，空 18 位**（空位在文末汇总，每个都写了「这个位置需要一个什么样的人」）。
> 编号一律是卡 `id`（`c_ct_*` / `c_md_*` / `c_dl_*`），括号里是职业 · 力/智/慧 · 等级。

排法上定了几条规矩：

1. **每人只出场一次**（卡数不够，重复出场会把这 18 个空位的意义冲掉）。
2. **机制只升不降**：D1~D4 是「一个机制、干净样本」，D5 起机制叠加，D10 全机制一起上。
3. **D1~D4 一个位都不空**——教学日必须有干净对照，空位一律放到 D5 之后（那时候"人手不够"本身就是戏）。
4. **极端数值往后放**：D4 教异常属性只用中度的（慧 20、总和 45 卡线），18/18/18、33/33/33、智 50 全留到 D10。

## 说明与选项

- **排班工具**：`tools/roster_editor.html` —— 双击用浏览器打开（不用起服务、不用装东西）。左边是 42 位候选人，中间是十天，右边是简历预览：属性条、特质、每条经验/专长的追问原文、以及「真假」结论（**造假程度 `fake_level`** / 有没有章 / 追问里会不会盖出假章 / 单项超 18 / 总和超 45 / 主属性对不对 / 简历上印的种族名）。
  `fake_level` 就是数据里那个 0~3 的字段（和特质里的 `fake0`~`fake3` 不同源，两个对不上时预览会提示一行）；「显示种族」读的是 `display_race`，填了就在预览里印那一串，空着就照 `race`。
  **可以直接读写 `data/days`**：点右上角「连接 data/days」选一次文件夹（Chrome / Edge 支持；选项目根目录或 `data/days` 都认），之后「重读」把现有名单读进来、「写回」把改好的写出去 —— 写之前会列出「哪天、几个人、磁盘上原来几个」让你确认，勾了「存 .bak」先把旧文件备份一份；只写和磁盘不一致的那几天，资源 `uid` 原样保留。
  浏览器不支持直连文件夹时（Firefox / Safari）用「导入文件…」挑 `day_XX.tres` 或 `roster_plan.json`，或者 `pwsh -File tools/apply_roster.ps1 -From roster_plan.json -Apply`。
  工具里的候选人是快照：改了 `data/candidates/*.tres` 之后跑一次 `pwsh -File tools/build_roster_editor.ps1` 重新生成 `roster_editor.html`（源模板是 `tools/roster_editor.template.html`）。
- **现在 `data/days/day_01.tres`~`day_10.tres` 还是旧占位名单**（指向 `c_0001`~`c_0025`、`c_0101`），没有动。这份名单确认后，用工具「连接 → 重读 → 写回」就能换成新名单：有卡的按上面顺序填，空位少写一个（`candidates` 数组长度 3/4/5/6/4…），`slots` 默认取「出场数 - 1」。
- **`day_01.tres` 眼下是例外**：为了验 `display_race`，临时把 `c_dl_0005` 皮尔莉 追到了第一天名单末尾（现在 4 位：`c_0101`/`c_0001`/`c_0002` 三个旧占位 + 皮尔莉），同时补上了它原来缺的 `day_index = 1`（缺这一行 DataDB 会当成无效天跳过）。按本文件的分工，皮尔莉的正位在 **Day 10**（智 50 那个极端值）—— 验完要么把她从第一天撤掉，要么干脆改分成「Day 1 用她」。
- **如果允许同一个人重复出场**（比如默汀在 D3 先以"史莱姆杀手"露个面），空位可以压到 10 个以内——但那样"人手不够"这条叙事就废了，所以我按不重复排。
